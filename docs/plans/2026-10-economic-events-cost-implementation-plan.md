## 1. Conclusion and the first slice to start next

Do not begin by rebuilding the calculation engine. `computeLots`, the selected-revision lot adapter, the knowledge selector, and the cash reconstruction query already exist. The major missing connections are evidence admission, writers, contracts consuming temporal identity, holdings quantity folds, coverage, and transport/reporting.

**The first small vertical slice, S0, is a read-only query returning event-generation readiness for explicitly selected transaction observations.** Connect published observation → account mapping/ownership → row identity → claim conflicts → results with reasons and a manifest. Select no policy, write no proposal/event/claim, and enable no existing writer. Use this as a shared basis for subsequent planner provenance checks and commit guards.

Rationale: the current registry classifies domestic and foreign securities histories as fingerprint-derived; even owner confirmation cannot admit them as provider-issued IDs. Adding a securities writer alone therefore cannot connect them to lots. Bank transfers have proposals/planners but lack publication and account-mapping rechecks. S0 makes these blockers verifiable in the current data model and can be implemented without waiting for the owner's financial policy decisions.

S0 does not complete #549. The first **financial event-generation** slice is a transfer between two of the owner's same-currency deposit accounts (S2), after S0 evidence conditions, explicit owner policy, and operational gates are met. Securities acquisitions/disposals, transferred cost basis, and P&L are separate slices.

## 3. S0: concrete contract from published rows to readiness

### Implementation locations

Proposed new files (names are provisional):

1. `packages/read-model/src/economic-row-readiness.ts`: keyed SQL loader for selected rows only.
2. `packages/domain/src/economic-row-readiness.ts`: pure evaluator calling the registry and `humanAdoptedRowIdentity` without duplicating admission rules.
3. `packages/application/src/query/economic-row-readiness.ts`: validate → load → evaluate → manifest digest.
4. Matching read-model/domain/application tests. Change existing `own-transfer-plan.ts` in S1, connecting the same provenance checks to its four planners.

S0 ends at the internal query. Add scoped read service/HTTP/MCP/UI separately as S0b. Open PRs #638/#641 change shared services and audit/transport; follow their integrated version instead of creating a parallel catalogue. S0 accepts inputs from an authorized caller; future transport must validate read scope **before reading content**.

### Inputs

- Exact keys; schema `economic-row-readiness-v1`.
- `family`: initially explicit diagnostics for `bank-movement` / `securities-execution`. This does not change family support.
- `rows`: 1–64 `{observationId, parseRunId}` entries; positive safe integers, duplicates rejected. 64 is a proposed bound for the new query, not a change to the existing 500-row proposal bound.
- `knowledge`: **current** only in S0. Refuse known-at to avoid implying historical publication/ownership queries. Do not derive economic order from clocks.
- Accept no caller overrides for policy, provider ID, account ID, ownership, instrument class, wrapper, or FX.

### Reads and identity

- Read only transaction observations actually present in the specified parse. Verify that the artifact/parser's current published parse selects that parse. Retain older observations but return proposed code `evidence_not_current`.
- Publication does not grant reuse permission. Define CORE0034 `evidence_use_restrictions` (`no-reuse | deleted | key-destroyed`) and the ref convention linking observations, parses, artifacts/originals in S0's ADR; check current restrictions in the same snapshot. Do not reuse restricted content; return refusal/restricted. Do not assume existing observation/eligible-identity views already check this. Pin CORE0038 `visibility_revision`; old contexts must not bypass current restrictions.
- Rederive the existing 5-tuple from source/producer/namespace/source-account/external-id; use current registry functions for provider-identity admission and alias classes. External-ID shape alone does not prove provider-issued origin.
- Follow account-identity observations from selected observations; require exactly one resolved current account mapping and pin its row ID/revision. Refuse zero/multiple/unresolved mappings. Do not let callers choose accounts.
- Refer to/reuse published/eligible sealed identity/current ownership semantics of keyed `cardSettlementOwnershipCtes("transaction")` (`packages/read-model/src/card-settlement-ownership.ts:44`). Explanation ref `account_mapping:<mapping-row-id>` differs from commit revision key `account_mapping:<source_account_id>`. Ownership keys are `ownership:<kind>|<account_id>`. Do not reuse explanation refs in `expectedRevisionsSql` (`storage-d1/src/core/operations.ts:42`).
- Do not infer own-transfer self-ownership from mapping. Return `ownership_unresolved` if the contract for determining self-ownership from adopted beneficial_owner or similar relations is unsettled. S0 only enumerates existing relation evidence/revisions for diagnostics; it never adopts ownership. Document how person principals correspond to self in relations before S1.
- Read key/alias live holders per book, matching the common guard. For cash, also check legacy card-settlement holds. Refer to existing keyed readiness/helpers to avoid materializing the full `live_consumption_claims` UNION in new SQL.
- Return current securities DB gates, selector gates, kind/state limits, and missing class/wrapper separately. Synthetic successful identity never means a writer is enabled.

### Results

- Return refs, family, **evidence readiness** `admitted | blocked | unavailable`, multiple closed reasons, and publication/mapping/ownership/registry/identity-epoch/holder pins per row.
- `admitted` means only that observation diagnostic conditions hold. Return `proposalEnabled:false` / `writerEnabled:false` separately; do not imply financial adoption is available.
- Overall results contain counts/refs and manifest/contextId. Never expose raw provider text, external-ID components, amounts, or account labels in diagnostics/audit/logs. Handle required aliases/keys internally and digest them in results; never build commit guards solely from results.
- Zero admitted rows proves neither an empty account nor complete transaction history. Keep family/history coverage unknown.
- New query code uses existing identity-refusal codes. Define additional closed codes for publication/ownership/missing guards/bounds in the implementation ADR/contract; proposed names here are not shipped enums.

### Time, correction, idempotency, and atomicity

- Separate original timestamps, parse-publication time, identity revision, and read-source revision. S0 is a current diagnostic and does not return historical adoption time.
- Return required metadata and selected rows' publication/mapping/ownership/holders from one SQL statement and snapshot. If multiple statements are needed, design start/end epoch/revision comparisons and bounded retry/refusal, proving those revisions capture changes to every read table. Equal last revisions alone do not prove coherence.
- Identical inputs/read pins/registry/evaluator versions produce identical contextId, independent of input order. Parse rollback, mapping/ownership corrections, and claim holds/releases produce new contextId.
- Read-only means **zero** SQL writes, receipts, decisions, proposals, claims, or economic-log records. Idempotency means reproducible reads, not operation receipts.
- Readiness is not authorization for a later writer. S1/S2 revalidate publication/mapping/ownership/identity/claims/current evidence restrictions at plan/approve/commit and include the commit guard in receipt reservation.
- Existing integration points are trusted `precondition` in `receiptReservationWrite` (`storage-d1/src/atomic/decision-commit.ts:19,39`) and `mutation.precondition` in `application/src/command/commit.ts:270`. Build no guard from caller-provided SQL or diagnostic digests alone.

### S0 acceptance conditions

- In synthetic stores using existing CORE schemas, bank rows with provider-ID origin pass evidence diagnostics; fingerprint securities rows are refused. Unsupported writers are always explicit.
- Explain reparsing, publication rollback, mapping corrections, unknown ownership, and claim conflicts individually; never reuse previously ready results when stale.
- Missing guard schema returns unavailable; 65 refs refuses the entire request; silently dropping missing rows is prohibited.
- Compare every related table before/after to prove zero writes. Safe results/audit/logs contain no amounts or provider text.
- Check keyed read plans without statistics and measure scaling with selected row counts. The first slice does not require scanning all accounts or history.

## 5. Connecting #546: replacing SQL alone is insufficient

The #546 instrument temporal journal/sealed members/atomic builder/coherent loader is an **assumed dependency not yet integrated**. Research expected CORE0078, but publication review confirmed [#564](https://github.com/risu729/kogane/pull/564) merged as `6714ea49f8ac046422a6e193a2fd97d9fef29bd0` and `0078_maintenance_change_provenance.sql` exists on main. It records actor/reason/decision provenance for maintenance revisions, not an instrument temporal journal.

CORE0078 is therefore occupied; #546's unpublished migration must be renumbered against main at implementation time. S3/S4 remain blocked until the actual journal API, complete members/seals, atomic builder, coherent loader, and tests are integrated. Matching numbers or #564's merge do not prove #546 is complete. Retain the research-time highest CORE0077 only as historical evidence.

Current main's `selectInstrumentTemporal` is a pure supplied-snapshot selector. It separates current/known-at from effective trade/position/price roles and handles half-open intervals, unknown validity, corrections, and complete membership. Lot consumption additionally needs:

1. **One unitRef → one mapping is insufficient.** `validLotAdapterRequest` (`lot-adapter.ts:322–348`) requires unique unitRefs; the Map at `:697` is keyed by unitRef. If code U means A in January and B in February, one selection cannot place both into separate books. New bindings key by `eventId@revision#securityLegIndex` and identity-reference role/time, pinning target instrument, decision version, and temporal context.
2. **Separate economic order from identity references.** Instrument identity follows the writer-verified trade role. Settlement-date lot policy must not change identity to a different settlement-date instrument. Positions/prices use their own roles.
3. **Do not remove selector flags to proceed.** Current selector `1512–1525` compares seal pins with current pins/epochs and reports `identity_changed`. A temporal consumer requires an ADR revising selector/seal version contracts for historical pin/epoch evaluation. Stripping existing flags in adapters is prohibited.
4. **The two sequences are independent.** Economic commitSeq E and instrument acceptanceSeq I are not the same number. At shared instant T, resolve each journal's knownAt≤T independently and pin both epoch/sequence/knownAt/standing/setVersion/contextId. Include all same-millisecond members under each journal's rules.
5. **Economic sequence alone does not determine paired cuts.** E.knownAt and instrument acceptance at the same timestamp have no ordering. The API must explicitly define shared-instant semantics and resolve I independently, or require paired pinned cuts. Decide this in the implementation PR as a reproducibility contract, not owner financial policy.
6. **Retained results do not resolve instants again.** Replay pinned E/I. New same-time appends change fresh contexts. Neither provisional cut permits complete results. Unknown identity validity/class/basis holds the affected book.
7. **Read all aliases but group by effective scope.** The current query expands current aliases and safely marks remapped-away aliases needs_review. Future queries resolve historical aliases by effective period/cut and verify buys/sales join the same book. Requested subsets alone cannot prove completeness.

Introduce S3's temporal lot consumer additively, retaining `queryLotsOnSelection`'s safe current behavior. Do not assume simple journal target mappings prove class, listing, currency, quoted quantity basis, or wrapper.
