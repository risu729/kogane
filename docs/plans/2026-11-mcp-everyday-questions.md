# Plan: everyday questions over MCP, in one or two calls

- Status: **proposed** (2026-11-19). An audit of the published MCP tools against the questions an owner asks
  every day, after the owner's request (2026-11-19, in Japanese: "do various MCP improvements; a lot of
  information takes many tool calls to get", then "you may add new tools if needed"). Gap G1 is implemented in
  the same pull request as this plan ([ADR 0125](../adr/0125-card-purchases-per-card-view.md)), and gap G2 on a
  branch stacked on it ([ADR 0125, amendment](../adr/0125-card-purchases-per-card-view.md#amendment-compact-purchase-lines-view-lines-2026-11-19));
  each is a published tool change and needs the owner's approval before merge. Gap G4 is implemented in its own
  pull request ([ADR 0123, amendment](../adr/0123-summary-detail-for-large-reads.md#amendment-cash-per-account-and-per-bank-in-one-call-collection-cash-2026-11-20)),
  a published tool change that needs the owner's approval too. The other gaps are proposals.
- Issue: [#1414](https://github.com/risu729/kogane/issues/1414) (done when: "how much is my next card bill, from
  which account, and will that account cover it?" and "which sources are failing?" take one or two calls, each
  answer under 8 KB).
- Related work in flight, not repeated here: Units A–F of the owner-shared design "card bills and collection
  status in one or two MCP calls" (proposal v2, 2026-11-19), and
  [#1446](https://github.com/risu729/kogane/pull/1446) (a cursor continues at another page size).
  - **A**: Vpass finalized statements counted the way `allCnt` counts them, so collector statements parse again.
  - **B**: `kogane.collection-quality.read` `view: status` (per source: last success, failures since,
    `recovered`, `state`, `notPublishing`).
  - **C**: `kogane.card-settlements.debit-accounts` `view: upcoming` (next bills, debit account, balance,
    `covers`).
  - **D**: `kogane.identity.read` `collection: account-list` (one line per account entity, readable labels).
  - **E**: `detail: summary | full` on `balances.read`, `schedules.read` and `collection-quality.read`, and
    `mustMatch` in cursor errors.
  - **F**: Vpass card names as read-time account labels.

selection, sorting the bounded month by exact amount in the domain rather than in SQL (the amendment's options).

## 4. Acceptance

- G1: one call answers "how much did I spend on each card" for a statement month or a usage month, under 8 KB
  for ten cards (ADR 0125's tests), with the route, the agent HTTP path and MCP answering the same `data`.
- G2 (implemented): one call answers "what did I spend on card X, on what" for up to 25 purchases and "my largest
  purchases this month" with the first page of `sort: amount`; every page within 7,168 bytes of `data` and the
  agent answer under 8 KB on the largest line shape; keyset pages without a duplicate or a skip; the route, the
  agent HTTP path and MCP answering the same `data` (the amendment's tests).
- Each later gap: its question in one or two calls, each answer under 8 KB at today's production scale, the same
  service for the route and the tool (ADR 0081), and a size test.
